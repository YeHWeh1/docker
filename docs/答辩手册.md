```powershell

```

## 看日志（出问题第一步）

```powershell

```

## 进容器里看文件

```powershell
docker exec -it hive-server sh
ls /data                  # 看到 6 个 CSV（宿主机 模拟数据 目录挂进来的）
ls /opt/hive/data/warehouse/ydsh_ods.db/   # 表的真实数据文件
```

| 端口 | 是谁 | 用途 |
|---|---|---|
| 10000 | HiveServer2 | beeline / JDBC 连这个 |
| 9083 | Hive Metastore | HS2 后台连它拿表结构 |
| 3307 | MySQL（宿主机） | 容器内是 3306，映射到宿主机 3307，避开本机 MySQL80 |

## 三条救急命令

```powershell
# 1. 容器起不来
docker compose up -d --force-recreate

# 2. Hive 连不上
docker compose restart hive-server; Start-Sleep 40

# 3. 全乱了
docker compose down; docker compose up -d
```
> 数据在 Docker 卷里，`down` 不会丢；只有 `down -v` 才会删卷。

# 第四部分 代码讲解

## 4.1 `sql/ods/create_ods.sql` —— 建表并导入

### 建库

```sql
create database if not exists ydsh_ods;
```

`if not exists` 保证重复执行不报错，脚本可以反复跑。

### 建表

```sql
create table if not exists ydsh_ods.ods_user (
  user_id string, user_name string, gender string, age int,
  ...
) row format delimited fields terminated by ','
tblproperties('skip.header.line.count'='1');
```

三个关键点：

| 写法 | 作用 | 不写会怎样 |
|---|---|---|
| `row format delimited fields terminated by ','` | 告诉 Hive 文件是逗号分隔 | 默认按 `\001` 切，整行变成一列 |
| `tblproperties('skip.header.line.count'='1')` | 读文件时跳过第 1 行（表头） | 表头会变成一条数据，行数变成 1001 |
| 字段类型 | `string` 兜底，`int` 只在有明确数值语义时用 | — |

**为什么大多用 `string`**：ODS 是贴源层，不做类型判断。如果 `age` 里突然出现 "未知"，
用 `int` 会导致导入失败或变 NULL。`string` 什么都能装。

> 追问 "age 为什么用 int"：因为年龄要参与均值计算，必须是数值类型；
> 转换不了的值会变成 NULL，正好被后面的缺失值处理捕获。

### 导入

```sql
load data local inpath '/data/ods_user.csv' into table ydsh_ods.ods_user;
```

- `local` 表示文件在**运行 beeline 的机器**的本地文件系统（这里是 hive-server 容器内）；
- `/data` 是容器里的路径，对应宿主机 `E:\dsh project\模拟数据`（compose 里挂的）；
- 数据文件会被**复制**到表的目录 `/opt/hive/data/warehouse/ydsh_ods.db/ods_user/`。

## 4.2 `sql/clean/00_quality_scan.sql` —— 五维度扫描

全部是 `select`，不改任何数据。

### 完整性的核心写法

```sql
sum(case when age is null then 1 else 0 end) as age_null
```

拆开看：

```
case when 条件 then 1 else 0 end   →  每行得到一个 0 或 1
sum(...)                            →  加起来 = 满足条件的行数
```

比 `count(*) where ...` 好在**一条 SQL 能同时算多列**，不用扫 10 遍表。

### 唯一性

```sql
select count(*), count(distinct order_id) from ods_order;
```

- `count(*)` = 15600（总行数）
- `count(distinct order_id)` = 15000（不同订单号数）
- 差 600 → 说明有 600 行是重复的

再看细节：

```sql
select order_id, count(*) c from ods_order group by order_id having count(*)>1;
```

`having` 是**分组后**过滤（`where` 是分组前），用来筛出"出现次数 > 1"的订单号。

### 有效性

```sql
select gender, count(*) from ods_user group by gender;
```

直接列出所有不同取值和频次，一眼看出 `男/女/M/F/male` 混在一起。

### 一致性

```sql
select length(register_date) len, substr(register_date,5,1) ch, count(*)
from ods_user group by length(register_date), substr(register_date,5,1);
```

用**长度 + 第 5 个字符**判断格式：
- 长度 10 且第 5 位是 `-` → `2023-11-25`
- 长度 10 且第 5 位是 `/` → `2023/11/25`
- 长度 8 → `20231125`

### 准确性

```sql
sum(case when age < 1 or age > 120 then 1 else 0 end)
```

## 4.3 `sql/clean/01_dwd_user.sql` —— 缺失值处理

### 为什么不能直接改原表

Hive 的表（非事务表）**不支持 `update`**。所以清洗的方式是：
**建一张新表，把"清洗后的查询结果"写进去**。

```sql
create table ydsh_ods.dwd_user as
select ...
from ydsh_ods.ods_user u
cross join (select cast(round(avg(age)) as int) as avg_age
            from ydsh_ods.ods_user where age between 1 and 120) m;
```

这就是 **CTAS**（Create Table As Select）：建表 + 灌数据一步完成。

> 答辩金句："Hive 的清洗是**用查询重新生成一份数据**，而不是对原表做 UPDATE。
> 好处是原表完整保留，随时可以对比、可以重跑。"

### 均值怎么用进来的

问题：Hive 不能写 `select ..., (select avg(age) from ...) from ...`（标量子查询支持有限）。

解法：**把均值算成只有一行的临时表，再和主表做笛卡尔积**。

```
主表 1000 行  ×  均值表 1 行  =  还是 1000 行（每行都带上这个均值）
```

`cross join` 就是"不带条件的 join"。

### 填充逻辑

```sql
case when u.age is null or u.age < 1 or u.age > 120
     then m.avg_age
     else u.age
end as age
```

读法：**空值或越界 → 用均值；否则 → 保留原值**。

### 为什么先过滤再算均值

```sql
where age between 1 and 120
```

如果不过滤，200 和 -3 会把均值拉偏。算出来是 41（922 条合法记录参与计算）。

### 标记列的必要性

```sql
case when u.age is null or u.age < 1 or u.age > 120 then 1 else 0 end as age_filled
```

填充进去的 41 是**人造数据**，不是真实的。留一个 `age_filled=1` 的标记，
下游看到就知道"这条是估的"，做分析时可以排除或加权。这是数据治理的基本要求。

## 4.4 `sql/clean/02_dwd_product.sql` —— 日期补全

### 思路

缺失的上架日期，用**同一二级类目里已有日期的中位数**补。比如"纸尿裤"里其他商品
大多在 2024 年上架，缺的那个也大概率是那个时候。

### 中位数怎么算

Hive 没有直接的 `median(日期)`，需要三步：

```sql
from_unixtime(
  cast(percentile(cast(unix_timestamp(launch_date,'yyyy-MM-dd') as bigint), 0.5) as bigint),
  'yyyy-MM-dd')
```

1. `unix_timestamp(日期,'格式')` → 日期转成秒数（数值）
2. `percentile(数值, 0.5)` → 取 50 分位 = 中位数
3. `from_unixtime(秒数,'格式')` → 秒数转回日期

### 左连接

```sql
left join (类目 → 中位数日期) d on p.sub_category = d.sub_category
```

`left join` 保证**所有商品都保留**，能匹配到类目均值就补，匹配不到就是 NULL。

### 兜底

```sql
coalesce(d.med_date, '1970-01-01')
```

`coalesce` 返回第一个非空值：类目里也没有有效日期时，退到 1970-01-01，
并靠 `launch_date_filled=1` 标记出来。

## 4.5 `sql/clean/03_dwd_order.sql` —— 去重

### 问题

15600 行，只有 15000 个订单号。同一订单号下可能有 2~3 行，
其中一部分是**整行完全一样**（重复录入），一部分是**内容有差异**（更新后没覆盖）。

### 窗口函数

```sql
row_number() over (
    partition by order_id
    order by order_time desc, pay_amount desc
) as rn
```

逐字解释：

| 部分 | 含义 |
|---|---|
| `partition by order_id` | 按订单号**分组**，每个订单号内部独立编号 |
| `order by order_time desc` | 组内按时间**倒序**排，最新的排第 1 |
| `row_number()` | 给每行发一个 1、2、3... 的序号，这就是 `rn` |

结果：每个订单号的第 1 行 `rn=1`，其余行 `rn=2、3...`。

### 为什么要套一层子查询

```sql
select ... from (select ..., row_number() over(...) as rn from ...) t where rn = 1;
```

因为**窗口函数不能直接写在 where 里**（SQL 执行顺序：先 where 再算窗口函数）。
必须先在子查询里算出 `rn`，外层再筛 `rn=1`。

### 为什么保留最新那条

业务含义：同一订单被提交多次，**最后一次提交代表用户的最终意图**。
若时间相同，再按金额降序（金额更完整的优先）。

去重结果：15600 - 600 = 15000，与 `count(distinct order_id)` 完全一致——
这就是"去重彻底"的证明。

# 第五部分 答辩问答（大概率被问的 15 个）

**Q1：为什么用 Docker，不直接装 Hive？**
A：Hive 依赖 HDFS + Metastore + MySQL 三个组件，手装要配环境变量、版本、权限，
换台机器就得重来。Docker 把整套环境打包，一条 `docker compose up -d` 就能复现，
团队里每个人环境一致。

**Q2：三个容器分别干什么？**
A：`meta-mysql` 存元数据（表名、字段、分区这类"目录信息"）；
`hive-metastore` 是元数据服务；`hive-server` 是 HiveServer2，接收 SQL、执行计算。
元数据和数据是分开存的——数据在 HDFS/本地文件，元数据在 MySQL。

**Q3：ODS 层为什么不直接清洗？**
A：ODS 是贴源层，原则是**原样保留**。好处是：数据出问题时能回溯到原始值；
清洗逻辑改了可以重跑；能对比清洗前后。如果一开始就改，脏数据长什么样就再也看不到了。

**Q4：为什么建新表而不是改原表？**
A：Hive 非事务表不支持 UPDATE。而且建新表可重复执行、可对比、可回滚。

**Q5：数据量多大？**
A：6 张表共 114,809 行。订单 15,600、明细 37,549、行为日志 60,000、用户 1,000、
商品 600、门店 60。

**Q6：怎么发现数据有问题的？**
A：五维度扫描——完整性（空值率）、唯一性（主键重复）、有效性（枚举合法）、
一致性（格式统一）、准确性（数值合理）。每条都有对应 SQL。

**Q7：age 填 41 是怎么算的？**
A：先筛出 1~120 区间的 922 条合法记录，求平均得 41.0，取整 41。
然后空值 51 条 + 越界 27 条 = 78 条统一填成 41，并打 `age_filled=1` 标记。

**Q8：为什么用均值不用中位数？**
A：任务书/手册给的方案是均值，且我们已经先剔除了 200、-3 这类异常值，
均值不会被污染。中位数更稳健，可以作为改进点提一句。

**Q9：email 缺失 19.3%，为什么不删这些用户？**
A：删掉会损失 193 个用户的订单、行为数据。保留空值 + `email_missing` 标记，
下游做用户画像时按需过滤，比直接丢数据更安全。

**Q10：重复订单怎么判定的？**
A：按 `order_id` 分组。586 组重复、涉及 1186 行、多出 600 行。
其中 394 组是整行完全一样，192 组是订单号相同但内容不同。

**Q11：为什么保留最新那条？**
A：同一订单多次提交，最后一次代表用户最终意图。若时间相同按金额降序。

**Q12：怎么证明去重是干净的？**
A：`count(*)` 和 `count(distinct order_id)` 都等于 15000，差值为 0。

**Q13：还有哪些脏数据没处理？**
A：四类——枚举中英文混用（男/M/male）、日期和手机号格式不统一、
负金额/超大金额/负数量、主外键一致性。这些按任务书安排在第 2 周之后处理，
现在只在报告里记录，不做修改。

**Q14：脚本能重复跑吗？**
A：能。建表用 `create table if not exists`，清洗用 `drop table if exists` +
CTAS，重复执行结果一致，不会叠数据。

**Q15：数据存在哪？容器删了会丢吗？**
A：数据文件在 Docker 卷 `hive-data`（挂到容器的 `/opt/hive/data`），
元数据在卷 `mysql-data`。`docker compose down` 不删卷，数据还在；
只有 `down -v` 才会删。

# 第六部分 三个"坑"（能讲出来会加分）

老师如果问"过程中遇到什么问题"，讲这三个，显得你真干过：

**坑 1：镜像拉不下来**
国内直连 Docker Hub 超时（IP 被污染）。解决：配镜像加速 + 走本机代理（Clash 7897），
速度从 0.5 MB/s 提到 20 MB/s。

**坑 2：metastore 起来就退出**
报 `ClassNotFoundException: com.mysql.cj.jdbc.Driver`——官方 `apache/hive:4.0.0`
镜像里**不带 MySQL 驱动**。解决：下载 `mysql-connector-j-8.4.0.jar`，
挂载到 `/opt/hive/lib/` 下，重启后 schematool 初始化成功。

**坑 3：容器重建后数据全丢**
Hive 的数据目录 `/opt/hive/data` 一开始没挂卷，容器一重建数据文件就没了。
解决：加命名卷 `hive-data` 持久化，之后重建、重启都不丢。

> 这三条说明：**你踩过坑并且能自己修**，比"一路顺利"更有说服力。
